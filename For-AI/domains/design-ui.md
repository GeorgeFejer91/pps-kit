## Scoped implementation and completion

Trace the existing control/state/backend flow, then change one requested screen
or segment. Preserve earlier completed segments and their ownership. Reuse
the installed Pretext typography contract; measure touched bounded labels and
inspect rendered DOM at relevant widths, zoom, and long-string states.

Build canonical assets and exercise real controls locally. Save inspected
screenshots under ignored `artifacts/`; check clipping, overlap, focus,
disabled/read-only behavior, and relevant errors. Use silent isolated browser
sessions unless a visible test is requested.

For exploration, present the working local preview and remain at
**local-preview** until accepted. Preview completion does not start packaging.
At source promotion, check Pages uses identical allowlisted compiled bytes.

The final planner action exports the verified local experiment JSON; the portable
audio bundle remains a separate action. Keep review evidence, instruction audio,
and long source filenames in disclosures so the approved plan remains readable.
Designer and Runner share `pps-resources/assets/ui/bounded-text.mjs` for Pretext
measurement. CSS owns wrapping and text size; user zoom is never reduced to fit.
Unsupported text layout is marked for DOM verification rather than claimed to fit.

The citation mapper joins the generated publication network to
`publication_study_reviews.v1.json`. Keep publication evidence, linked template
availability and native qualification separate. Search and publication/study
URL parameters use the existing paged list and detail pane; counts come from
the projection. A template link opens preparation/preview, not a qualification
claim. Failed data loads expose a retry. The detail grid reflows using its
available container width, including when text is enlarged.

Hosted finalization holds authoring controls inert until browser storage
settles. Project restores and late preview/audio results cannot change that
pending snapshot. Failed storage releases the editable draft; successful
storage releases the locked profile and export action. Keep delayed-storage
and request-order regression checks alongside real browser interaction checks
in `apps/designer/frontend/tests/verify-browser-workflows.mjs`.

Runner audio preparation follows native instruction/block occurrences through
the compatibility command `prepare_first_audio_block`. Retire prior media at
playback and gate boundaries; device preparation, arm and start remain separate
local actions. Click gates use the participant response surface, button gates
retain the native gate ID, and timed waits expose no manual continuation. Group
advancement uses the current native revision, clears the prior part's detailed
summary and requires a fresh schedule inspection. Whole-experiment completion
depends on the native group receipt, not completed-part counts alone. Selection
also shows a bounded, paged read-only assessment of existing result files;
selection never infers resume or timing qualification from those files. The
compiled-browser sequence regression uses a deterministic native boundary;
native execution and durable receipts remain covered by the Rust owner tests.

Portable hosted exports embed referenced premade WAVs, spoken instruction clips
and browser uploads. Resolve premades from their existing inventory/colocated
spoken manifest and verify SHA-256 before rebinding audio references into the
bundle; missing or changed bytes fail export. Bound a single asset to 64 MiB and
the audio bundle to 256 MiB. Browser soundchecks resolve restored uploads from
IndexedDB and cancel pending fetch/decode publication when the profile changes.
Study URLs honor generated record aliases and disclose a split into current
study records rather than silently presenting one as equivalent.

New static block previews preserve the selected baseline strategy and include
instruction/jitter prefixes in looming and tactile onset times. Catch/audio-only
rows have no tactile onset. Existing restored snapshots remain unchanged and
require native timing enrichment and operator review before acceptance. The
actual 204-row Study 5 browser preview is a regression fixture; native assembly
receives complete rows plus the existing strip planner's explicit variant choices.

The Tauri Designer composes the same HTML/local planner with explicit native
commands for generation, file picking, portable import/export and draft storage.
Native failures stay native. Source algorithms require explicit opt-in; a
revision change cancels pending generation and completed ingredients invalidate
later previews. `apps/designer/src-tauri/README.md` records the connected slice,
local verification and proposed identity. Hosted Segment 6 is descriptive;
complete participant/phase order must come from the sealed native planner and
be reviewed before acceptance. Physical output remains unmeasured; existing
calibration validation and level ceilings remain enforced.

Native execution acceptance is separate from portable profile locking. Build a
full native review, inspect verified Segment 5 timing and paged participant/part
occurrences, then explicitly accept the sealed revision. Editing or restarting
revokes native acceptance. Preparation verifies every immutable part and the
group before exposing its folder; split runs hand off the group manifest.
Stationary control generation preserves moving audio, uses explicit V2 opt-in,
and invalidates later review. Preserve source hash/loudness/comparator metadata
through form collection and embed comparator bytes separately in portable export.
