## 2026-06-13
- Preloaded runner-ready experiment profiles remain read-only for editing, but Segment 6's final `Save Design and Start Experiment Runner` / `Open Experiment Runner` action is an allowed profile-run action. If a profile project is missing generated local Segment 2-6 artifacts, the final runner-launch route may materialize the missing trial sequences, audio-tactile files, trial pool, accepted block CSVs, and run setup manifest on demand before launching native Focus Mode. Profiles that fail the Segment 0-4 recreation gate still return the explicit profile-readiness error instead of launching.
- Profile read-only status is now backend-enforced as well as UI-enforced: direct design mutation payloads for loaded profiles are rejected, custom forks require a non-empty study name, long custom study names receive compact hash-suffixed folder IDs while preserving the full project label, and the profile runner-launch path ignores design/run-setup edits while still accepting participant launch context. Segment 0 now lists saved custom studies from the local dashboard project registry and can reopen a custom project by its registry ID without clearing or rebaking downstream artifacts.
- Runner recording/runtime decisions now belong to native Focus Mode / `PPSExperimentRunner.exe`, not Segment 6. Segment 6 remains the experiment-preparation handoff surface with planned participants, one-part versus two-part structure, instruction preloads, block-order preview, and runner launch. The runner exe collects participant code, name, age, handedness, gender, and a per-name checkbox controlling whether the real name is emitted in LSL/session-start metadata; otherwise the LSL/session metadata uses a generated pseudonymous code. The runner also owns the `Belts and Suspenders` full-audio backup WAV checkbox and the `Top up missed tactile trials at end of each part` checkbox. LSL/event recording is treated as the standard protocol: live `PPSMarkersV2`/`PPSTriggerCodes` is always attempted, while local marker CSV/XDF mirrors and trigger dictionaries remain standard recoverable outputs.
- `SessionRunnerController` now writes `session_metadata.json` at run start and emits redacted session metadata in the `session_start` LSL/event marker plus LSL/local-XDF stream descriptors. The metadata includes participant demographics, capture policy, run timestamp, experiment/project/template fields when available, manifest paths/hashes, and design/run-setup snapshots from the HTML GUI. Local metadata may contain the entered name; LSL/session-start metadata omits it unless the operator explicitly checks the name-sharing box.
- Missed-trial top-up is now part-aware. With top-up enabled, the runner finalizes and materializes one operator-approved top-up block at the end of each experiment part, so a pre/post experiment can produce one Part 1 rescue block and one Part 2 rescue block. Top-up manifests are part-specific in two-part sessions, rescue rows replay missed tactile trials from the same part, fillers preserve row structure, and top-up misses are not recursively topped up.
- Implemented the recording-layer validation architecture for actual-condition runner checks. Normal runs now keep `events.csv` always on, write internal `PPSMarkersV2`/`PPSTriggerCodes` marker mirrors to `lsl_markers.csv` and local `lsl_markers.xdf`, and can optionally write a data-heavy local audio evidence WAV from the mixed output callback after routing, gain, clipping limits, and tactile-channel mouse-click marker injection. Physical electrical loopback is now explicitly validation-only and is compared against those software layers with `validation_protocols/scripts/compare_recording_layers.py`; it is not required during participant experiments. Dashboard wording changed from backup loopback to audio evidence WAV while retaining compatibility payload keys.
- Ran the accepted actual-condition recording-layer validation at `artifacts/validation_runs/recording_layer_actual_condition_20260613_anchor/` and `artifacts/validation_runs/recording_layer_alignment_20260613_anchor/`. One prepared 88 s Segment 5/6 block was played through Komplete ASIO with conservative validation gains (`audio_gain = 0.0005`, `tactile_gain = 0.02`) while physical loopback, local audio evidence WAV, local events/XDF, and internal LSL marker mirrors were captured. The comparison passed with physical-minus-digital latency 33.462 +/- 0.013 ms, right-minus-left skew -0.023 ms, tactile-minus-audio skew 0.011 ms, zero dropped digital buffers, no clipping, 146/146 internal event/marker IDs, sample-anchored LSL timestamp p95 error below 0.000001 ms, and 20/20 physical response-marker pulses recovered with 0.000 ms residual jitter after fitting the common recording offset. Use this as the current best evidence for validating the experiment-time event/LSL and audio-evidence layers against physical loopback.
- Updated `TimingEventHub` so later callback-derived scheduled events in a block are timestamped from the block's `audio_sample_zero` sample-time anchor plus `sample_index / sample_rate`. This fixes the observed late-block marker drift from relying on each callback buffer's PortAudio timing fields independently.
- `validation_protocols/reports/latency_reliability_validations.tex` now has a main conclusion section for the final latency report. It states in plain language and technical language that WAV-derived timing and LSL/event-derived timing agree where events are physically visible, after accounting for the stable 33.462 +/- 0.013 ms physical output/input/capture delay. It also adds summary tables for accepted latency trials and per-recording-method reliability.
- Published-study profile acceptance is now a hierarchical Segment 0-4 gate. Segments 5-6 are native toolkit materialization and runner handoff; they do not decide whether a paper has enough published PPS-task information for inclusion.
- Every preloaded profile must have non-empty Segment 2 trial-sequence rows with selected source labels for audio boxes. Segment 2 is also the place to encode fixed or jittered ITI timing; the dashboard labels this control as `Jitter / ITI box`.
- Two-speaker analog looming/receding setups are apparatus provenance, not a separate audio source and not an automatic structural blocker. Extract the reported near/far trajectory, duration, source type, SOAs, baseline strategy, and repetition counts, then recreate the motion with the toolkit's binaural spatial renderer. Exact original gain/envelope files remain missing provenance only for author-stimulus equivalence.
- The current profile gate covers 21 templates: 7 pass, including 6 published profiles (`matsuda_2021_four_directions`, `barumerli_2026_arm_movement_exp1`, `barumerli_2026_arm_movement_exp2`, `noel_2015_bodily_self`, `pfeiffer_2018_lateral_perihead_left_to_right`, and `serino_2015_peri_trunk_exp1`) plus the unpublished Study 5 profile; 12 have missing publication parameters and 7 have toolkit structural gaps.
- The retired `two_speaker_intensity_crossfade_gain_law` blocker must not be reintroduced. Real structural blockers remain things like direction-coupled tactile-only baselines, body-part anchored coordinates, physical multi-speaker arrays/switching, Gaussian speaker-array amplitude fields, rear-hemifield trajectory families, body-scaled distance modes, tactile waveform/calibration needs, voice-key responses, and Unity/3D Tune-In behavior.
- Segment 6 now uses the visible label **Preload Instruction Audio Clips** for run-level instruction audio. It has slots for before experiment, before each block, after each block, between conditions, and after experiment, with click-target, timed-delay, or runner-button continuation. The Study 5 default profile preloads the original local Study 5 clips: `General_Instructions.wav` (85.708 s), `Pre-Block_Instruction.wav` (8.418 s), `Post-Block_Instruction.wav` (8.829 s), `InterimMessage.wav` (10.109 s), and `FinishMessage.wav` (7.001 s). Imported Segment 6 clips are local-only, stored under `6_experiment_run_setup/instruction_library/`, saved in `dashboard_run_setup.instruction_profile`, copied into participant `instructions/` folders, and logged by `SessionRunnerController` without contributing continuation clicks to trial-response analysis.
- Focus Mode resume is now ledger-aware. The dashboard writes ignored local activity state under `local_data/dashboard_state/` (`experiment_activity_log.jsonl` plus `last_experiment.v1.json`) when designs are edited, Segment 6 is prepared, sessions are prepared, and runners launch. `PPSExperimentRunner.exe --last-experiment` reopens the last launchable experiment; the resume order is explicit session manifest, valid last session manifest, valid last run setup manifest, newest prepared Segment 6 setup, then manual file picker. Study 5 defaults to a two-condition Segment 6 setup displayed as Condition 1/Condition 2 while preserving internal `pre`/`post` phases for analysis.

## 2026-06-05

- Added `For-AI/` as tracked conceptual memory for future agents.
- The toolkit goal is a public, reusable audio-tactile PPS toolkit centered on Study 5 but extensible to published audio-tactile PPS paradigms.
- The Windows app should feel ready to use, not like a script collection.
- The stimulus/trial designer should separate stimulus design from trial design and save/load settings for reproducibility.
- Randomization should happen in the background. It should not be a primary GUI tool.
- Background randomization should preserve reproducibility, use no-immediate-repeat trial ordering by default, and counterbalance block order for any number of blocks.
- The GUI should become more intuitive: researchers define PPS design parameters, while implementation mechanics stay automatic or documented.
- Literature metadata should only track variables that can be implemented in the GUI, runner, analysis, or template system.
- `Example-configs/Pfeiffer_EJN2018.zip` was added as reference material for Pfeiffer et al. (2018)-style lateral peri-head auditory stimuli. It contains a MATLAB spherical-head/pink-noise simulator and pre-rendered left/right WAVs; future support should distinguish imported baked audio from generated Study 5-style SOFA/HRIR looming.
- Public-release boundaries remain strict: do not commit raw participant recordings, generated participant WAVs, name-bearing outputs, APKs, VR code, model downloads, SOFA/HRIR files, background music, or third-party assets without verified redistribution rights.
- The 3DTI render contract now records explicit listener head geometry and gain assumptions. Render configs/manifests carry head diameter/radius, 3DTI high-quality anechoic model details, customized ITD, propagation delay, distance attenuation, near-field effect, and relative digital level normalization. The Pfeiffer preload aligns 3DTI listener head radius with the reference simulator's `head_diam = 0.18 m`; Pfeiffer dB constants are stored as provenance only because the reference script peak-normalizes its WAV output.
- The Qt designer now has three workflow tabs: `Stimulus Design`, `Trial Assembler`, and `Experiment Runner`. `Trial Assembler` replaces the flat trial-design view with condition controls, trial-family toggles, block assembly, trial preview, and participant block-order preview. The runner tab started as a preflight/launcher; the later 2026-06-14 runner cleanup retires the old console runner as a public/operator path.
- The published-paradigm preload library was initially stress-tested and expanded to 17 profiles. Partial profiles covered Ferri 2015, Taffou 2014, Teneggi 2013, Serino 2015 peri-trunk/peri-hand/front-back variants, Galli 2015 wheelchair PPS, Noel 2015 walking PPS, and Lerner 2021 3D PPS. Profiles marked `partial` are structured runnable scaffolds only; exact replication still requires missing GUI/model support such as proprietary ecological sounds, social/locomotor/VR factors, speaker-array crossfades, body-scaled distances, and multi-direction batch trajectories.
