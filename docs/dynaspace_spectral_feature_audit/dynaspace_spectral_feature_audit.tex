\section*{Executive Decision}

The smartphone DynaSpace stimulus should not be copied as an opaque WAV into PPS-kit. It should be decomposed into a parameterized dry burst train plus a 3DTI/SOFA trajectory renderer. The useful smartphone-study features are: a broadband Gaussian white-noise burst train, a strong but not extreme rising distance/intensity envelope, the 6.4 m to 0.2 m constant-bearing trajectory, log-spaced tactile anchors, and room/externalization cues visible in the low interaural coherence of the baked WAV. Those are worth adopting as explicit parameters.

The features that PPS-kit/3DTI should handle instead of imitating by raw spectral hacks are HRTF spectral filtering, ILD, ITD, near-field corrections, future trajectory angles, and any controlled reverberation/direct-to-reverberant behavior. The current PPS-kit proxy file does not yet match the raw DynaSpace audio: it is continuous rather than burst-train-like, much higher in RMS level, less bright, highly interaurally coherent, and has a stable opposite-signed ILD/ITD convention relative to the DynaSpace raw files. The target 3DTI framework is a better conceptual approach, but the present proxy render is not yet a faithful DynaSpace-style implementation.

\section*{Scope and Inputs}

This audit isolates the raw spectral, temporal, level, and binaural features in the DynaSpace Android audio files used by Roussel et al.'s smartphone PPS validation study \cite{roussel2025}. The original raw WAV files were measured from a private local archival clone of the public DynaSpace source repository \cite{dynaspace_repo}. The raw files are not redistributed here. PPS-kit artifacts in this folder are derived metrics, plots, TeX, and PDF only.

\section*{Signal Quality Assessment}

The DynaSpace raw looming WAV is technically clean for a behavioral stimulus: it has no clipping, large headroom, high crest factor consistent with a pulse train, and a stable 33-burst temporal pattern. Its level is low on average because most of the file is sparse/noisy and because distance/reverberation were baked into the render. The raw fixed file is also clean, but its peak and RMS are much lower than the looming file. That fixed-vs-looming level gap is not a file-quality problem; it is a design property that can become an interpretive problem if a future study tries to attribute all facilitation to spatial proximity rather than level/salience.

The PPS-kit proxy files are also technically clean, but they are not DynaSpace-equivalent. They are continuous broadband noises, not burst trains; they are peak-normalized close to full scale; the looming proxy has a stronger gain ramp than the raw DynaSpace looming file; and the proxy binaural image is much more coherent. This makes the present proxy useful as a runnable placeholder, but not a final smartphone-style replication stimulus.

\section*{Best-of-Both-Worlds Generation Protocol}

\begin{enumerate}
  \item Generate a dry, mono Gaussian white-noise burst train: 33 bursts, 30 ms dry burst duration, 10 ms raised-cosine rise/fall, 65 ms silent interval, median peak spacing 95 ms, seed recorded in metadata. Keep a source-spectrum option that can target the raw DynaSpace brightness without pretending that spectrum matching is spatial rendering.
  \item Use the DynaSpace trajectory profile already encoded in PPS-kit: 6.4 m to 0.2 m, 2.105 m/s, ear level, constant-bearing left approach, tactile anchors at 105, 1625, 2385, 2765, 2955, and 3050 ms. Preserve the ability to change azimuth/elevation/endpoints for future studies.
  \item Render with native 3DTI high-quality mode when available. Use SOFA HRIRs, HRIR interpolation, customized ITD/head model, propagation delay, 6 dB-per-distance-doubling direct-path attenuation, and near-field corrections. Use FABIAN as the redistributable default; use LISTEN only in private or after a license audit.
  \item Add an optional DynaSpace-room/externalization layer: early reflections plus late reverberation or BRIR/Ambisonic reverb. Tune it with QC targets rather than by ear: lower IACC than the dry proxy, documented direct-to-reverberant settings, and retained direct-source lateralization.
  \item Provide two comparator modes. A \textit{DynaSpace replication} mode keeps the far fixed source at 640 cm with the original-style distance/level logic. A \textit{clean causal} mode adds matched-level controls so spatial proximity, temporal expectancy, and loudness/salience can be separated.
  \item Add render QC acceptance checks for every generated WAV: no clipping; declared peak/RMS/SPL policy; 33 detected bursts and 95 ms median IOI; active looming level span near the chosen target; channel-sign validation; expected ILD/ITD direction for the requested azimuth; IACC/DRR report if reverb is enabled; and all trajectory anchors stored in sidecar JSON.
\end{enumerate}

\section*{Implementation Consequences for PPS-kit}

\begin{itemize}
  \item The next toolkit change should be a \texttt{dynaspace\_burst\_train} source generator, not another pre-rendered WAV copy.
  \item The DynaSpace profile should expose two level-policy presets: \texttt{smartphone\_replication} and \texttt{matched\_level\_control}.
  \item The renderer should prefer native 3DTI for DynaSpace-style publication stimuli; the Python SOFA reference path is acceptable for preview/proxy but should be flagged as simplified.
  \item Reverb/BRIR should be optional but first-class. The original smartphone stimulus used reflections/reverb, and the measured low IACC shows that current PPS proxy externalization is not equivalent.
  \item Before changing left/right signs, run a channel-orientation audit. The raw files and current proxy disagree in ILD/ITD sign, and that can be a coordinate convention issue rather than a true stimulus mismatch.
\end{itemize}

\section*{Bottom Line}

It is worth incorporating several DynaSpace stimulus features into PPS-kit, but only as explicit, testable generation parameters. The strongest additions are the burst-train source, DynaSpace-level trajectory anchors, controlled rising level, and optional reflection/reverb/externalization layer. The features that 3DTI should own are spatial cues: HRTF spectrum, ILD, ITD, near-field behavior, propagation delay, distance attenuation, and arbitrary future trajectories. The raw smartphone WAV is best treated as an audit target and validation reference, not as the renderer.
